# 帆船专注游戏｜核心设计宪法 v1.0

## 00｜冻结说明

这份文档定义产品核心。后续漂流瓶、鲸鱼、海怪、NPC、船歌、小王子星球、钓鱼、港口、船只收集等想法，都进入创意池和功能设计，不再反向修改核心原则。

核心可以被解释、被落地、被验证，但不轻易扩写。

## 01｜三句话结构

现实中，你在专注。

游戏里，你在航行。

时间久了，这个世界会记得你来过。

## 02｜最高原则

不用奖励逼玩家回来，而用世界的延续感邀请玩家回来。

这句话高于具体功能。任何奖励、成长、剧情、UI、活动、数值设计，只要开始让玩家产生“今天不做就亏”“我要为了游戏刷专注”的感觉，就应该被重写。

## 03｜四条护栏

### 现实优先原则

游戏永远服务于现实中的专注，而不能反过来让玩家为了游戏去专注。

所有奖励系统都要检查：它有没有开始诱导玩家为了游戏本身去刷专注时间？一旦答案是“有”，就说明奖励过强了。

### 安静权

玩家拥有安静的权利。专注期间，任何内容都不能要求玩家回应。

海豚、鲸、船员音乐、远处海怪都可以出现，但不应该弹出“点击”“选择”“领取”。错过也没有关系。这个世界不是在抢注意力，而是在替玩家保管这段时间。

### 世界记忆大于玩家数据

数据可以存在，但情绪反馈优先于数字反馈。

不要只让数据库记得玩家航行了多少次，要让世界表现得像它记得玩家。航行次数、总时长、海里数可以藏在航海日志里，但核心反馈应该来自船、港口、地图、人物、照片、旧信、天气、船员回忆和世界变化。

### 回来原则

无论玩家离开一天、一个月还是一年，回来都不应该面对惩罚、红点、过期奖励和责备。

世界只是继续欢迎他。没有连续签到中断。只有这段旅程停了一阵子。

## 04｜三个基础判断

以后增加任何功能、动画、奖励、剧情、UI，都先问三个问题：

1. 它有没有让我更期待下一次专注？
2. 它是在制造陪伴，还是制造压力？
3. 它有没有留下时间经过的痕迹？

## 05｜第一阶段核心循环

第一阶段只做一件事：把“启航 → 航行 → 抵达”做到非常舒服。

启航是开始专注的小仪式。航行是安静陪伴。抵达是一次专注完成后的世界反馈。

## 06｜专注中的交互边界

航行中主要是观看和陪伴，不是管理和点击。重要交互尽量放在启航前、抵达后、休息期。

UI 要弱化。不要任务表，不要明显进度条，不要每日任务，不要连续签到，不要错过奖励。

如果玩家想知道剩余时间，可以点一下船或船员，由字幕自然地说：“还有三分钟靠岸。”

## 07｜暂停、离开与回来

暂停不是失败，而是落帆、停泊、避风、休息。

离开可以有生活感和小故事，但不能比完成航行更划算。暂停、离开、忽略过程可以产生小事件，但不能鼓励刷暂停、刷关闭、刷奇遇。

合适的暂停收获包括少量鱼、乘客照片、浮木、旧绳子、碎贝壳、船员一句话、航海日志片段。不适合的暂停收获包括核心稀有船只、大量资源、可刷高价值奖励、必须暂停才会出现的关键进度。

## 08｜成长与故事

成长应该像世界自然回应玩家的航行，而不是系统要求玩家完成指标。

不要写“再完成 5 次专注解锁新船”。更适合写成：“旧航海图上的坐标逐渐清晰了。也许再经过几段航程，就能找到那艘失踪的船。”

人物愿望比任务更重要。不要做任务表和进度条。

## 09｜时间痕迹

时间痕迹分三层：

- 数字痕迹：总航行次数、总航行时间、总海里数、第一次启航日期。
- 视觉痕迹：船身变旧、航海日志变厚、地图被填色、港口变化、船上出现旅程带回来的装饰。
- 叙事痕迹：旧 NPC 再次出现、以前送出的信有回音、过去发现的岛后来变成补给点、船员记得某次航行。

## 10｜技术和美术方向

第一版继续使用 Godot。当前目标是验证第一片海，而不是追求大型商业引擎生态。

默认美术方向是 2D 手绘或绘本感、竖屏 9:16、温暖、安静、治愈、陪伴。真正决定画面质量的是分层美术素材、Spine 或类似动画工具、清晰的动画状态，而不是 Unity 或 Godot 本身。

## 11｜创意池边界

漂流瓶、鲸鱼、海怪、NPC、船歌、小王子星球、钓鱼、港口变化、船只修复、旧物赎回、乘客照片、失踪船线索都可以继续扩展。

但它们必须服从核心宪法：服务现实专注，尊重玩家安静权，让世界记得玩家，欢迎玩家回来，用延续感邀请玩家，而不是用奖励逼迫玩家。
